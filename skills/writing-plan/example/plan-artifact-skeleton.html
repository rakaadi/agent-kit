Feature Implementation Plan

Start from this scaffold when generating plan-${implementation-task}.html. Extend the content, but keep the panel order and the card anatomy stable unless the user explicitly asks for a different layout.

Main job of the header: give a reviewer the title, the goal, the target architecture shape, the relevant stack, and the execution metadata before they scroll into task detail.

Goal

State the concrete change and the runtime behavior that must not regress.

Architecture

example-foundation Phase 1 Depends on: Nothing

Title: Create the shared access layer.

Description: Explain the smallest reviewable slice that unlocks later tasks.

  • Keep exact file paths, commands, and API names visible.
  • Do not repeat dependency information inside the lower metadata grid.

Out of Scope

Main point: state the tempting adjacent work that this plan will not absorb.

  1. Name unrelated platform upgrades, tooling setup, or parallel refactors that stay outside this workstream.
